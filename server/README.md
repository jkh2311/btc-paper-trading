# BTCUSDT RMI 24시간 서버 — 실주문 OFF

이 디렉터리는 기존 아이폰 PWA의 **1분봉 차트 화살표**와 같은 RMI 신호를 계산하는 별도 서버 프로세스입니다. **현재는 신호 관찰기이며 주문 전송 코드는 없습니다.** GitHub Pages에 업로드해도 Node 서버가 저절로 24시간 실행되지는 않습니다.

## 기존 차트 신호와의 일치

- RMI(모멘텀 5, 길이 14), Wilder 지수 평균, 기존 `index.html`의 `rmiSeries` 계산식과 동일
- 직전 확정 1분봉 RMI가 85 미만이고 최신 확정봉에서 85 이상이면 **SHORT**
- 기존 모의매매 v61 차트 LONG 조건으로 복구: 직전 확정 1분봉 RMI가 20 초과이고 최신 확정봉 RMI가 20 이하로 내려가면 **LONG**. 신호준비 및 40분 유효기간 기능은 현재 비활성 상태로 별도 보관했습니다.
- 진행 중인 봉의 신호는 사용하지 않습니다. 기존 차트 화살표처럼 **확정봉 신호**입니다.
- 바이낸스 USDⓈ-M REST 1분봉으로 시작 데이터 확보, WebSocket 1분봉 **마감(x=true)** 이벤트에서 신호 판단
- 서버 시작 및 네트워크 재연결 시 과거 신호는 실행하지 않으며, 중복 방지를 위한 최근 봉 시각을 파일에 저장합니다.

## 로컬 실행 (Node.js 22 이상)

```sh
cd server
npm test
npm start
```

실행 후 로컬 상태 확인:

```sh
curl http://127.0.0.1:8787/health
```

응답의 `mode: SIGNAL_OBSERVER` 및 `liveOrders: false`는 의도된 상태입니다. 실제 신호는 터미널의 JSON 로그에서 `event: rmi_chart_signal`로 기록됩니다. 외부에서 건강 상태 API에 접속할 수 없도록 `127.0.0.1`에만 바인딩됩니다.

선택적인 환경변수: `RMI_UPPER=85`, `RMI_LOWER=20`, `RMI_HEALTH_PORT=8787`, `RMI_STATE_PATH=./server-data/rmi-state.json`. 아이폰 앱에서 RMI 상·하단 수치를 변경했다면 서버 설정도 수동으로 일치시켜야 합니다. 기본값은 85/20입니다.

## 24시간 운영을 위한 다음 단계

사용자가 소유한 VPS 또는 항상 켜진 서버에서 Node.js 22 이상을 설치하고, systemd 같은 서비스 관리자로 프로세스를 시작해야 합니다. 이 GitHub 커밋은 **서버가 실제로 가동 중이라는 뜻이 아닙니다.** 연결 끊김·재시작 시 서버는 과거 신호를 재전송하지 않고 새로운 실시간 신호부터 수집합니다.

**실주문 활성화는 아직 구현하지 않았습니다.** 수동 주문 및 기존 바이낸스 보호주문을 서버가 건드리지 않으며, API 키나 비밀키도 필요하지 않습니다. 실주문 단계에서는 주문의 중복 방지, 기존 포지션/미체결 주문 조회, 주문 크기 한도, 체결 확인, 손절·익절 거래소 등록과 확인, 등록 실패 시 신규 주문 중단, 통신 실패의 불확정 주문 재조회, 운영자 긴급 중단을 별도 검증해야 합니다. **주문 기능을 검증하기 전 실거래 활성화 금지.**

차트 화살표는 확정봉 기준입니다. 차트에서 과거 기록을 훑어보는 것과 서버가 새 봉을 감지하는 것은 다르며, iPhone PWA의 화면이 꺼져도 서버는 독립적으로 수집합니다.
